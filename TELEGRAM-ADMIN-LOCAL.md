# Проверка административного Telegram-бота с Mac

**Один токен при запуске на localhost недостаточен.** В текущей версии бот получает команды через webhook: Telegram отправляет HTTPS-запрос на сайт. Long polling (`getUpdates`) не реализован. Без публичного HTTPS-адреса Telegram не может достучаться до Mac.

Для локальной проверки нужен HTTPS-туннель (например Cloudflare Tunnel или ngrok). Он временно делает приложение на Mac доступным извне. Это не перенос на VPS, но это публичный доступ к локальному серверу. Используйте отдельного тестового бота и тестовые данные. Без туннеля можно запускать автоматические тесты с подменённым Telegram API.

## 1. Подготовить сайт

Установите Node.js 24 LTS, откройте корень проекта в VS Code. Создайте приватный `.env` из `.env.example`, если его ещё нет; существующий файл не перезаписывайте. Храните `.env` вне Git (`chmod 600 .env` на Mac).

Для теста задайте отдельный постоянный каталог данных вне `public`, например:

```dotenv
HOST=127.0.0.1
PORT=3000
ORBITA_DATA_DIR=./data-telegram-test
ORBITA_PAYMENTS_MODE=cloudpayments
ORBITA_LIVE_PAYMENTS_ENABLED=false
TELEGRAM_ADMIN_BOT_ENABLED=false
MARKETS_MODE=off
```

Не указывайте ключи реального магазина для этого теста. Локальный `npm run local` создаёт временную базу и очищает внешние настройки — для живого бота его использовать **не нужно**.

Запуск в первом терминале:

```sh
node --env-file=.env server.mjs
```

## 2. Получить HTTPS-адрес

При установленном Cloudflare Tunnel во втором терминале:

```sh
cloudflared tunnel --url http://127.0.0.1:3000
```

При необходимости установить на Mac: `brew install cloudflared`. Альтернатива — собственный настроенный ngrok. Прочитайте условия выбранного провайдера туннеля; его доступность и отсутствие промежуточной страницы проверки браузера нужно проверить отдельно.

Скопируйте выданный HTTPS-origin, например `https://выданное-имя.trycloudflare.com`. Не подставляйте этот пример буквально. Адрес временного туннеля может измениться при повторном запуске.

## 3. Настроить отдельного бота

Создайте бота в BotFather (`/newbot`). Нужны **token** вида `числа:секрет` и **username**, а не только ID. Для административного бота и бота клиентских уведомлений используются разные токены.

Заполните `.env` непосредственно на Mac:

```dotenv
ORBITA_PUBLIC_ORIGIN=https://ВАШ-АДРЕС-ТУННЕЛЯ
ORBITA_REQUIRE_ADMIN_MFA=true
TELEGRAM_ADMIN_BOT_ENABLED=true
TELEGRAM_ADMIN_BOT_TOKEN=ТОКЕН_ИЗ_BOTFATHER
TELEGRAM_ADMIN_BOT_USERNAME=имя_бота
TELEGRAM_ADMIN_WEBHOOK_SECRET=СЛУЧАЙНЫЙ_SECRET
TELEGRAM_ADMIN_DRAFT_TTL_MINUTES=30
```

Secret создайте командой `openssl rand -hex 32` и сохраните в `.env`; это отдельное значение, не токен BotFather. Перезапустите первый терминал той же командой `node --env-file=.env server.mjs`. Открывайте сайт через HTTPS-адрес туннеля: при заданном HTTPS-origin cookie и защита запросов рассчитаны на этот адрес, не на localhost.

## 4. Подключить свой аккаунт

1. Зарегистрируйтесь через HTTPS-сайт в этой тестовой базе. Если уже зарегистрированы именно в ней, используйте существующий аккаунт.
2. В третьем терминале назначьте администратора (подставьте свою почту):

```sh
node --env-file=.env scripts/manage-access.mjs admin you@example.com
```

3. Войдите в сайт, настройте MFA на странице безопасности и сохраните резервные коды. Если включена доставка почты — подтвердите адрес.
4. Зарегистрируйте webhook:

```sh
node --env-file=.env scripts/setup-telegram-admin.mjs --set
node --env-file=.env scripts/setup-telegram-admin.mjs --status
```

5. В редакции откройте **Telegram · сигналы**, получите код подключения и отправьте `/connect КОД` в личный чат с ботом. Одного `/start` для административного доступа недостаточно.

## 5. Что проверить вручную

- `/start`, `/help`; без привязки публикация запрещена.
- `SBER 312 307 325`: появляется предпросмотр; до подтверждения идея не публикуется. Instant Publish для первой проверки выключен.
- Подтверждение создаёт одну идею в веб-редакции. Повторное нажатие не создаёт дубль.
- Подтвердить вход, изменить стоп, закрыть идею; проверить последовательность и историю на сайте.
- Проверить EXCLUSIVE-идею с аккаунтами PRO, EXCLUSIVE и без подписки.
- Отключить привязку на сайте: прежние команды не должны публиковать сигналы.
- Пометить учебные публикации отдельно; не переносить тестовую базу в рабочую.

Mac, сервер Node и туннель должны работать и иметь интернет. Сон Mac, закрытие терминала или обрыв туннеля прерывают работу. При смене адреса обновить `ORBITA_PUBLIC_ORIGIN`, перезапустить сервер и повторить `--set`. Один бот имеет один webhook: не подключайте тестовый токен одновременно к production. Поле ошибки в `--status` может хранить последнюю старую ошибку; проверяйте фактическую доставку нового сообщения.

Для круглосуточной работы нужен VPS с постоянным HTTPS-доменом. Реальный чат с вашим ботом не проверен автоматически: тесты используют вымышленные токены, временные базы и контролируемые ответы Telegram.

## Автоматические проверки без токена

```sh
npm ci
npm run test:telegram
npm run check:ui
```

Для браузерных тестов один раз установите браузер: `npx playwright install chromium`. `test:telegram` запускает 79 проверок парсера, связки аккаунтов, webhook, повторных доставок, публикаций, отзыва прав и Radar. `check:ui` включает веб-настройки бота и сопровождение сигнала в редакции. Ключи реальных провайдеров и каталоги операторских данных в эти тесты не передаются.
