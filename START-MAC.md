# Локальная Орбита на MacBook

Нужен Node.js 22 или новее; рекомендуется [Node.js 24 LTS](https://nodejs.org/en/download). После его установки перезапустите VS Code. Запуск сайта не требует Docker, платёжных ключей, почты или Telegram.

## VS Code

1. Откройте папку проекта `Orbita` с файлом `package.json` (File → Open Folder).
2. Нажмите **F5** и выберите **Orbita: локальный сайт с тестовыми аккаунтами**. Зависимости установятся из `package-lock.json`, затем запустится локальный сервер.
3. Откройте **http://127.0.0.1:3000/account.html**. Ссылки и тестовые данные появятся во встроенном терминале VS Code.
4. После входа администратором откройте **http://127.0.0.1:3000/admin.html**. Клиентский кабинет: **http://127.0.0.1:3000/dashboard.html**.

Если F5 занят системной функцией, используйте Run → Start Debugging или Fn+F5. Терминал с сервером должен оставаться открытым. При первом открытии проекта VS Code может попросить подтвердить доверие к папке: проверьте, что это ваша копия `r4vemode/Orbita`.

## Другие способы запуска

Дважды откройте `START-LOCAL.command`. Если macOS не разрешает запуск скачанного файла, откройте терминал VS Code в папке проекта и выполните:

```sh
bash START-LOCAL.command
```

Либо самостоятельно:

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm run local
```

Если порт 3000 уже занят, остановите предыдущий экземпляр. Команда `npm run beta:local` выберет свободный порт и напечатает его адрес.

## Тестовые аккаунты

| Роль | Email | Что проверять |
| --- | --- | --- |
| Администратор | `editor@local-beta.example.test` | Публикация и сопровождение идей, Radar, контент, настройки |
| Клиент Pro | `pro@local-beta.example.test` | Идеи Pro, личные позиции, Radar, калькулятор |
| Клиент Exclusive | `exclusive@local-beta.example.test` | Отдельный доступ Exclusive |
| Без подписки | `free@local-beta.example.test` | Отсутствие доступа к платным идеям |

**Пароль создаётся заново при каждом запуске и печатается в терминале рядом с email.** Он общий только для четырёх учебных аккаунтов данного запуска. В репозитории и архиве паролей от ваших аккаунтов нет. Учебным адресам подтверждение письмом не требуется: это отметка только внутри временной базы. Для одновременного сравнения ролей используйте обычное и приватное окна браузера.

Этот режим запускает отдельную временную базу с явно обозначенными учебными идеями и событиями. Он игнорирует реальные настройки провайдеров и существующую базу. Почта, Telegram, биржевые подключения и реальные платежи выключены. После остановки через Ctrl+C или Stop в VS Code временная база удаляется; для следующего запуска будут новые пароль и данные. Не вводите здесь рабочие персональные данные.

## Проверки

```sh
npm test
npm run check:mvp
npx playwright install chromium
npm run check:ui
```

Последние две команды нужны только для браузерных автотестов, не для просмотра сайта в Safari/Chrome. Отчёты и учебные снимки экранов сохраняются в `qa-artifacts/`. Эти проверки используют отдельные временные базы и не отправляют реальные платежи или сообщения.

Для необязательной проверки симулированной оплаты: `npm run beta:local -- --payments --port=3000`. В админке `/payments-admin.html` можно задать результат тестового заказа. Это локальный симулятор без обращения к CloudPayments.

Обычный `npm start` использует постоянную базу и **не создаёт** эти тестовые аккаунты. Если нужны сохраняемые собственные данные, используйте отдельную инструкцию [START-HERE.md](START-HERE.md); не подменяйте её базу временными учебными данными.
