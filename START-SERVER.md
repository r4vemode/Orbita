# ORBITA — следующий шаг с сервером

Сервер ещё не выбран. Подготовлен комплект для **Ubuntu 24.04 LTS, 2 vCPU, 4 ГБ RAM и SSD от 40 ГБ**. Для первой беты нужен один VPS с постоянным диском, публичным IP и доступом по SSH-ключу.

1. Выбрать VPS и домен. Доступ к кабинету провайдера защитить MFA; закрытый SSH-ключ хранить у себя.
2. Направить DNS домена на VPS. Открыть для сайта 80/443, SSH ограничить своим административным адресом. Порт приложения 3000 наружу не открывается.
3. Установить Docker Engine и Compose, загрузить чистый release проекта в `/srv/orbita/app`.
4. Подготовить приватные каталоги данных и копий, скопировать `deploy/.env.example` в `deploy/.env`, указать домен и собственную фразу резервного копирования.
5. Проверить настройки и запустить контейнеры. Затем зарегистрировать владельца на сайте, назначить ему администратора доверенной командой и подключить MFA.
6. Проверить сайт на фактическом HTTPS-адресе. Реальные продажи включать отдельно после документов, писем, оплаты и возврата.

Точные команды, обновление и восстановление — в [deploy/README.md](deploy/README.md). Пароли, ключи, `.env` и личную базу не передавайте в чат или Git.

Одновременно добавлена встроенная поддержка: клиенту — `/support.html`, редакции — `/support-admin.html`. Она доступна без подписки после входа и работает без почтового провайдера. Порядок — в [docs/support.md](docs/support.md).


## Проверить сборку до выбора VPS

На машине с локальным Docker из корня проекта выполните:

```sh
npm run check:container
```

Команда использует собственные временные контейнеры и тома, не открывает порты и удаляет свои ресурсы после проверки. Для первого скачивания закреплённого базового образа заранее выполните `docker build -t orbita-rehearsal .`; каждая команда автоматического прогона ограничена 30 секундами. На этой машине Docker должен работать без `sudo` перед npm либо весь прогон должен выполняться в заранее подготовленной доверенной среде с доступом к Docker.

Проверяются непривилегированный процесс, код только для чтения, регистрация и Secure cookie, «Моя Орбита» и ограничения доступа, MFA администратора, зашифрованная копия с восстановлением, остановка и перезапуск. Отчёт — `qa-artifacts/container-*/report.json`. Успех локального прогона не проверяет DNS, публичный TLS, firewall или реальные письма и платежи. Фактический результат и оставшиеся условия — в [отчёте от 2 ноября](docs/launch-preparation-2026-11-02.md).
