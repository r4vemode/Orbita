# ORBITA — проверка проекта 31 октября 2026 года

Проверены серверные модули, браузерные скрипты, страницы, служебные команды и инструкции. Все воспроизведения используют временные базы, вымышленные аккаунты и фиктивные провайдеры. Рабочие пользовательские данные не читались и не изменялись.

## Исправленные ошибки

| Область | Ошибка и результат |
| --- | --- |
| Доступ | Сессия, роль или подписка могли быть отозваны во время медленной отправки формы. Изменяющие API повторно проверяют полномочия перед действием; операции аккаунта проверяются внутри транзакции. |
| MFA | Отзыв сессии во время проверки пароля прекращает настройку; повышение до администратора не позволяет завершить ранее начатое отключение обязательной MFA. Поздний ответ с ключом не показывается другому аккаунту. |
| Открытые страницы | Кабинет, обучение и калькулятор проверяют текущую личность и доступ при возвращении во вкладку и периодически. При изменении очищаются прежние данные и выполняется соответствующий переход. Приватные экраны редакции скрываются до проверки; временный обрыв связи сохраняет черновик и положение курсора, смена пользователя очищает модели и поля. |
| Оплата | Сбой одного заказа не блокирует остальные активации и возвраты. Дополнительная транзакция закреплена за исходным заказом, включая старые записи ручной проверки. |
| Формы | Смена аккаунта не смешивает состояние оплаты. Изменение настроек уведомлений во время сохранения не теряется. Медленная публикация блокирует смену контекста редактора, сохраняя соседний черновик. |
| Сохранность | Базы аккаунтов, идей, обучения и новостей проверяют тип и размер файла до чтения. Подменённые ссылки отклоняются. Неудачная запись и исчерпание ревизии сохраняют прежний файл. Ключ MFA читается через проверенный дескриптор. |
| Radar и MOEX | Учебные и реальные события не объединяются. Опрос источников восстанавливается после сбоя сохранения статуса. Некорректная дата состава индекса отклоняется. |
| Расчёты | Калькулятор использует точные временные отметки событий, сохраняя порядок сделок внутри одной минуты. Некорректные даты личной сделки и бесконечные производные результаты отклоняются. |
| Запуск и команды | Закрытые страницы и скрипты ограничивают нагрузку до чтения аккаунтов. Проверка готовности не возвращает успех после начала остановки. Импорт новостей и назначение администратора запрещают публичный каталог данных. Учебный импорт блокируется в production. |
| Telegram | Bridge использует тот же `ORBITA_DATA_DIR`, что и сервер, проверяет приватность каталога и не следует ссылкам на сессию/ленту. |

## Проверка

| Проверка | Результат |
| --- | --- |
| `npm test` | 281/281 успешно; добавлено 49 регрессионных проверок |
| `npm run check:mvp` | 11 групп успешно: реальные HTTP-запросы, перезапуск, зашифрованная копия и восстановление |
| `npm run check:ui` | 171/171 успешно, Chromium 154.0.8037.57, `ru-RU`, `Europe/Moscow` |
| Python bridge | 8/8 офлайн-тестов успешно |
| Статическая проверка | 149 JS/MJS-файлов без синтаксических ошибок, 379 локальных ссылок HTML без отсутствующих целей; Python-файлы разобраны синтаксически |

Профильные регрессии воспроизводят медленные HTTP-загрузки, смену пользователя, отказ хранилища и платёжные повторы, а не только успешный путь. Действующие пользовательские аккаунты и публикации в проверках не участвовали.

`npm audit` и `npm audit --omit=dev` не обнаружили известных уязвимостей в установленных зависимостях; внешних runtime-зависимостей у сервера нет. Это проверка по базе npm, а не проверка всей безопасности приложения.

## Следующие шаги для MVP

1. Провести закрытую бету с участниками: регистрация, выбор тарифа, идея, личная сделка, сопровождение и обращение в поддержку. Собирать ошибки по единому шаблону из `beta-testing.md`.
2. Подготовить реальные авторские материалы, контакты поддержки и сведения исполнителя; проверить опубликованные документы.
3. После появления внешних настроек пройти реальные письма, CloudPayments с выдачей/отзывом доступа и возвратом, разрешённые источники данных.
4. Пройти основные сценарии на физических iPhone и Android.

Хостинг, внешний HTTPS, реальные платёжные операции, письма, Telegram и биржевые подключения в этом прогоне не настраивались. Проверки не являются независимым пентестом или доказательством отсутствия всех ошибок.
