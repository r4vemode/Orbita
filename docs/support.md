# ORBITA — обращения в поддержку

Клиент открывает `/support.html` из кабинета, страницы помощи или футера. Нужен вход в аккаунт; оплаченная подписка не требуется. Это позволяет обратиться по поводу оплаты, истёкшего доступа или неполадок в кабинете.

## Клиент

1. Нажать «Новое обращение», выбрать раздел, заполнить тему и описание шагов.
2. При необходимости указать страницу из списка и UUID-код из ошибки. Параметры адреса, токены и заголовки браузера не собираются.
3. После отправки сохранить номер `ORB-000001`. Ответы команды и состояние видны в той же переписке.
4. Дополнение к решённому обращению снова открывает его. При конфликте версий текст остаётся в форме; перед повтором нужно проверить обновлённые сообщения.

Письма, Telegram и внешние уведомления об ответе пока не отправляются. Есть обновление вручную и фоновая проверка открытой клиентской страницы. Срок ответа не обещается автоматически.

Если ответ сервера потерян, кнопка повтора в этой вкладке использует прежний идентификатор и тот же текст. Неполное подтверждение не стирает набранное. Несохранённые поля находятся только в памяти вкладки; при её закрытии браузер предупреждает о потере черновика. На другом устройстве доступны уже сохранённые сообщения.

## Редакция

В `/support-admin.html` доступна общая очередь: поиск по номеру, теме и email, фильтры раздела и статуса, переписка и история изменений. Этот раздел закрыт ролью администратора и существующей защитой MFA.

Статусы: новое, в работе, ждём клиента, решено. Ответ редакции переводит заявку в ожидание клиента. Сообщения и история не удаляются через API. Временный сбой проверки аккаунта скрывает приватный экран и сохраняет поля; смена пользователя очищает данные.

## Данные и ограничения

- Клиент читает только свои обращения; чужой UUID возвращает 404. Email владельца виден только редакции.
- Тема — до 120 символов, сообщение — до 3000. Вложения не принимаются; любая разметка в сообщениях отображается текстом.
- До 5 новых обращений за 24 часа и 5 незавершённых одновременно. Повторное открытие тоже учитывает активный предел.
- До 20 клиентских дополнений за 24 часа; в одном обращении до 50 сообщений и 200 событий истории.
- В аккаунте до 100 обращений; в хранилище до 2000 и 16 МиБ. При заполнении прежняя история сохраняется, новая операция отклоняется.
- `support.json` находится в приватном `ORBITA_DATA_DIR`, проверяется при запуске и входит в зашифрованную копию и восстановление. Записи атомарные, с блокировкой и правами 0600; ссылки и повреждённая структура отклоняются.

Пароли, cookie, API-ключи, резервные коды и платёжные реквизиты не следует отправлять в свободном тексте. Код не добавляет их к обращению автоматически. Вложения и адреса с токенами не используются для диагностики.

## API

| Метод | Назначение |
| --- | --- |
| `GET /api/support` | Свой список |
| `POST /api/support` | Создать обращение с `requestId` |
| `GET /api/support/:id` | Своя переписка |
| `POST /api/support/:id/messages` | Дополнить с `requestId`, `revision`, `message` |
| `GET /api/admin/support` | Общая очередь редакции |
| `GET /api/admin/support/:id` | Переписка для редакции |
| `PATCH /api/admin/support/:id` | Изменить статус с `requestId` и `revision` |
| `POST /api/admin/support/:id/messages` | Ответить от редакции |

Создание принимает только `requestId`, `subject`, `category`, `message`, `page`, `reference`. Повтор идентичного намерения возвращает существующий результат до проверки лимитов и устаревшей ревизии; изменение текста с прежним ключом даёт 409. Пользователь и полномочия повторно проверяются после загрузки тела и внутри последовательной записи.
