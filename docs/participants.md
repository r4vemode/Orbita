# Позиции участников Мосбиржи

Раздел показывает распределение открытых позиций физических и юридических лиц по направлениям LONG и SHORT. Источник FUTOI относится к **фьючерсам**. Тикер акции помогает найти связанный инструмент, но данные фьючерса нельзя выдавать за позиции в самой акции.

Например, поиск SBER может вести к доступному фьючерсу на Сбербанк. В карточке остаются видны код фьючерса, базовый актив, время биржевого среза и источник. Состав отображаемого справочника не является подтверждением актуального состава индекса Мосбиржи.

## Открыть раздел

В кабинете доступна страница `/participants.html` — «Позиции участников». Она использует существующий аккаунт: нужен действующий Pro, Exclusive либо роль администратора. Отслеживаемые инструменты сохраняются отдельно для каждого пользователя.

В интерфейсе есть вкладки «Отслеживаемые», «Акции и индекс», «Все инструменты», поиск и фильтр рынка. Карточка показывает отдельные полосы LONG/SHORT, проценты юрлиц и физлиц, код связанного фьючерса и время среза. Подробности открываются в диалоге.

Фильтр «Бумаги индекса Мосбиржи» доступен только после получения состава на дату. Пока состав не подтверждён, а также в учебном режиме, выбрать его нельзя. Вкладка «Акции и индекс» при этом остаётся общим справочником соответствующих базовых активов.

Если реальные данные не подключены, можно явно нажать **«Открыть учебный пример»**. Все его значения вымышлены; режим обозначен на странице и в карточках. Кнопка «Вернуться к биржевым данным» возвращает к фактическому состоянию источника. Отказ источника не переключает страницу на демо автоматически.

Быстрая локальная проверка:

1. Выполнить `npm run beta:local` и войти под учебной ролью Pro, Exclusive либо администратора, которую выведет команда.
2. В кабинете открыть «Позиции участников», затем нажать «Открыть учебный пример».
3. Найти `SBER`, добавить в отслеживаемые и открыть подробности. В примере LONG: физлица 70%, юрлица 30%; SHORT: физлица 35%, юрлица 65%.
4. Обновить страницу, снова открыть учебный пример и проверить список «Отслеживаемые». Затем вернуться к биржевым данным: без подключения источника там останется состояние отсутствия данных.

`beta:local` использует отдельную временную базу, а не рабочие аккаунты и публикации. Для обычного сохранённого локального проекта используется `npm start`.

## Как читать проценты

Проценты рассчитываются отдельно внутри каждого направления по **объёму открытых контрактов**:

| Показатель | Формула |
| --- | --- |
| Доля юрлиц в LONG | `legal.long / (legal.long + individual.long) × 100` |
| Доля физлиц в LONG | `individual.long / (legal.long + individual.long) × 100` |
| Доля юрлиц в SHORT | `legal.short / (legal.short + individual.short) × 100` |
| Доля физлиц в SHORT | `individual.short / (legal.short + individual.short) × 100` |
| Нетто категории | `long − short` |

Пример с вымышленными значениями:

| Категория | LONG, контрактов | SHORT, контрактов | Нетто |
| --- | ---: | ---: | ---: |
| Физлица | 700 | 350 | +350 |
| Юрлица | 300 | 650 | −350 |
| Всего | 1 000 | 1 000 | 0 |

В таком примере на физлиц приходится 70% объёма LONG и 35% объёма SHORT, на юрлиц — 30% LONG и 65% SHORT. Это **доли контрактов, а не доли людей**. Нельзя читать их как «70% всех физлиц покупают». Нормализация FUTOI учитывает `clgroup=FIZ/YUR`, положительный `pos_long` и отрицательный `pos_short`: для объёма SHORT используется модуль исходного значения. Поля `pos_long_num` и `pos_short_num` в расчёте не используются; их наличие не позволяет считать процент контрактов долей уникальных людей или компаний.

Для одной карточки нужны согласованные по времени строки обеих категорий. Нельзя складывать срезы разных минут, дубли ответов или семейство фьючерсов с его отдельными контрактами. Нулевой знаменатель, отсутствующая категория или несогласованные итоги означают отсутствие достоверной процентной оценки; это не нулевой интерес участников.

## Граница данных по акциям и индексу

FUTOI не является реестром владельцев акций или универсальной статистикой коротких позиций по всем акциям IMOEX. Связанный фьючерс — отдельный инструмент; его участники и позиции могут отличаться от спотового рынка. При отсутствии связанного инструмента либо данных интерфейс должен сообщать об отсутствии покрытия.

Актуальное вхождение бумаги в индекс требует отдельной датированной выгрузки состава. Статический справочник тикеров не подтверждает состав индекса на сегодня, а отсутствие данных по фьючерсу не означает отсутствие позиций в акции.

Связь тикера и семейства фьючерсов определяется биржевым справочником `RFUD`: `ASSETCODE` → `SECTYPE`. Неоднозначная связь остаётся без покрытия. Код из учебного примера не становится постоянной настройкой реального адаптера: состав и обозначения инструментов меняются.

## Настройка источника

Параметры находятся в [`.env.example`](../.env.example). Обычный запуск не загружает `.env` сам: при использовании файла выполнить `node --env-file=.env server.mjs`.

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `MOEX_POSITIONS_ENABLED` | `true` | Доступность раздела; строго `true` либо `false` |
| `MOEX_POSITIONS_MODE` | `off` | `off` — без внешних запросов; `moex` — биржевой адаптер |
| `MOEX_API_KEY` | пусто | Необязательный серверный ключ Bearer; не попадает в ответы API |
| `MOEX_POSITIONS_INTERVAL_SECONDS` | `300` | Общий фоновый опрос, от 60 до 3600 секунд |
| `MOEX_POSITIONS_STALE_MINUTES` | `30` | Возраст биржевого снимка для отметки устаревания, от 5 до 1440 минут |

Без ключа используется фиксированный адрес `https://iss.moex.com/iss`, с ключом — `https://apim.moex.com/iss`. Произвольные адреса источника через браузер или параметры запроса не принимаются. Реальная доступность FUTOI зависит от подписки и условий Мосбиржи; наличие адаптера не выдаёт права на распространение данных.

Сервис запрашивает:

- `/analyticalproducts/futoi/securities.json?date=YYYY-MM-DD` — позиции FUTOI.
- `/engines/futures/markets/forts/boards/RFUD/securities.json` — связь базовых активов и семейств фьючерсов.
- `/statistics/engines/stock/markets/index/analytics/IMOEX/tickers.json?date=YYYY-MM-DD` — необязательное подтверждение состава индекса на дату. Запрос без даты возвращает историю состава и не подходит для подтверждения текущего вхождения.

Биржевое время берётся из `tradedate` и `tradetime` в часовом поясе `+03:00`. Поле `systime` может отражать техническую загрузку исторических данных и не используется как время рыночного снимка. Категории сопоставляются по тикеру, сессии, номеру последовательности, дате, времени и дате торговой сессии. Отдельные сроки одного семейства не суммируются поверх уже полученного семейного среза.

Опрос общий для приложения: открытие нескольких кабинетов не создаёт отдельного потока запросов к Мосбирже. Успешный снимок сохраняется в приватном кэше. Ошибка источника не меняет его исходное время и не создаёт новые значения; интерфейс отмечает устаревание. Если инструмент пропал из новой выгрузки, его прежний снимок сохраняется с отметкой устаревания. Более старый биржевой срез не заменяет более новый. Сбой подтверждения состава не делает статический список актуальным составом IMOEX. Данные со слишком большим ответом, некорректными строками или незавершённой выгрузкой нельзя выдавать за полный свежий срез.

## Доступ и хранение

Страница, исполняемый клиентский код и все `/api/participants` требуют действующего Pro, Exclusive либо администратора. Без аккаунта API отвечает `401`, без подходящего действующего доступа — `403`. Проверка применяется также к демонстрации, справочнику и персональному списку, а не только к навигационной ссылке.

| Запрос | Результат |
| --- | --- |
| `GET /api/participants/config` | Безопасное состояние источника без ключа |
| `GET /api/participants` | Последние реальные снимки либо пустое состояние |
| `GET /api/participants/demo` | Явно вымышленные учебные снимки; реальный кэш не изменяется |
| `GET /api/participants/coverage` | Справочник и состояние подтверждения состава индекса |
| `GET /api/participants/watchlist` | Тикеры текущего пользователя |
| `PUT /api/participants/watchlist` | Замена своего списка: `{ "symbols": ["SBER"] }` |
| `GET /api/participants/SBER` | Доступный реальный снимок; без снимка — отсутствие данных. История не моделируется |
| `GET /api/participants/SBER?demo=1` | Учебные подробности, только при явно выбранном демо |

Список хранит стабильный тикер базового актива, например `SBER`; текущий код семейства фьючерсов передаётся отдельно как `futuresCode`. Списки пользователей изолированы. Тело изменения ограничено; неизвестные тикеры и лишние поля отклоняются. Проверяется источник изменяющего запроса.

`participants.json` располагается в приватном `ORBITA_DATA_DIR`, вне `public`. В нём находятся последний кэш, сведения о покрытии и персональные списки. Запись атомарная с блокировкой; повреждённый либо подменённый символьной ссылкой файл не считается новой пустой базой. Файл входит в зашифрованное резервное копирование и проверку восстановления. Учебная выдача не заполняет реальный кэш и не моделирует историю позиций.
