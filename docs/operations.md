# ORBITA — проверка готовности сервера

Этот документ описывает технический барьер между локальной разработкой и рабочим размещением. Проверка не отправляет письма, не обращается к CloudPayments или Telegram и не печатает значения секретов.

## Быстрая проверка

Запускайте команду в том же окружении и с тем же `ORBITA_DATA_DIR`, которые использует сервер:

```sh
npm run preflight
```

Она проверяет Node.js, сочетания переменных, структуру существующих JSON-баз и возможность выполнить атомарную запись в каталог данных. Отсутствующие внешние интеграции в локальном режиме отмечаются предупреждениями.

Перед открытием продаж выполните:

```sh
npm run preflight -- --production
```

Строгая проверка требует внешний HTTPS-origin, email поддержки, рабочий режим CloudPayments, Resend, обязательную MFA администратора и зашифрованные резервные копии в отдельном каталоге. Telegram остаётся отключаемой интеграцией, но частично заполненная или некорректная конфигурация считается ошибкой.

Если переменные лежат в локальном `.env`, Node.js 20.6+ может загрузить их явно:

```sh
node --env-file=.env scripts/preflight.mjs --production
node --env-file=.env server.mjs
```

## Проверки хостинга

- `GET /healthz` возвращает `200`, пока процесс способен отвечать HTTP.
- `GET /readyz` возвращает `200` только после проверки структуры хранилища и пробной атомарной записи. Во время остановки или ошибки диска ответ — `503`.
- `GET /api/admin/readiness` требует действующую сессию администратора и возвращает статусы компонентов без адресов каталогов, ключей, токенов и пользовательских данных.

Проверка готовности не опрашивает внешних провайдеров. Краткий сбой CloudPayments, Resend или Telegram не должен перезапускать исправный сервер. Доступность провайдеров контролируется отдельно по реальным тестовым операциям и их кабинетам.

## Размещение первой версии

Файловое хранилище рассчитано на один экземпляр ORBITA. Разместите процесс за HTTPS-прокси и подключите один постоянный приватный диск. Не запускайте несколько реплик с общей сетевой папкой: файловые блокировки проекта не являются распределёнными.

Каталог резервных копий должен быть отдельным от `ORBITA_DATA_DIR` и `public`. Фраза шифрования хранится в секретах хостинга, отдельно от самих копий. До допуска к продажам восстановите одну копию в новой тестовой папке и проверьте вход, MFA, идеи, подписки и платёжный журнал.

## Ошибки и остановка

Неожиданный серверный сбой получает безопасный `errorId`. Тот же идентификатор, маршрут и технический код появляются в stderr; тело запроса, cookie, email, пароль и токены туда не пишутся. Пользователь может передать поддержке только `errorId` и время события.

При `SIGTERM` или `SIGINT` сервер сначала снимает готовность, перестаёт принимать новые соединения, останавливает таймеры и ожидает HTTP-запросы, очередь уведомлений, письма и уже запущенные фоновые операции. Если за десять секунд завершение не произошло, соединения закрываются, а процесс завершается с кодом `1`, чтобы хостинг зафиксировал ошибочную остановку.
