# ORBITA — проверка готовности сервера

Этот документ описывает технический барьер между локальной разработкой и рабочим размещением. Проверка не отправляет письма, не обращается к CloudPayments или Telegram и не печатает значения секретов.

## Быстрая проверка

Запускайте команду в том же окружении и с тем же `ORBITA_DATA_DIR`, которые использует сервер:

```sh
npm run preflight
```

Она проверяет Node.js, сочетания переменных, структуру существующих JSON-баз, включая `legal.json` и `radar.json`, и возможность выполнить атомарную запись в каталог данных. Проверка `RADAR_CONFIGURATION` отклоняет неверные флаги, тарифы и параметры источников, не раскрывая адреса и ключи. Она не выполняет внешние запросы: успешный статус настроек не подтверждает получение корпоративных данных. Состояние каждого адаптера смотрите в редакции Radar. Отсутствующие внешние интеграции, неподготовленные документы и выключенные рабочие продажи в локальном режиме отмечаются предупреждениями.

Перед открытием продаж выполните:

```sh
npm run preflight -- --production
```

Строгая проверка требует внешний HTTPS-origin, email поддержки, рабочий режим CloudPayments, Resend, обязательную MFA администратора, зашифрованные резервные копии в отдельном каталоге, опубликованную редакцию документов и явные `ORBITA_LIVE_PAYMENTS_ENABLED=true` и `ORBITA_RECEIPTS_CONFIRMED=true`. Подтверждение чеков — заявление оператора о подготовленном процессе, а не проверка реального чека или подключение кассы. Пока условия не выполнены, рабочие продажи остаются закрытыми. Telegram остаётся отключаемой интеграцией, но частично заполненная или некорректная конфигурация считается ошибкой. Порядок подготовки документов — в [legal-documents.md](legal-documents.md).

Для работы используйте поддерживаемую LTS-версию Node.js, рекомендуется актуальный Node.js 24 LTS (минимум проекта — 22). Если переменные лежат в локальном `.env`, загрузите их явно:

```sh
node --env-file=.env scripts/preflight.mjs --production
node --env-file=.env server.mjs
```

## Проверки хостинга

- `GET /healthz` возвращает `200`, пока процесс способен отвечать HTTP.
- `GET /readyz` возвращает `200` только после проверки структуры хранилища и пробной атомарной записи. Во время остановки или ошибки диска ответ — `503`.
- `GET /api/admin/readiness` требует действующую сессию администратора и возвращает статусы компонентов без адресов каталогов, ключей, токенов и пользовательских данных.

Проверка готовности не опрашивает внешних провайдеров. Краткий сбой CloudPayments, Resend или Telegram не должен перезапускать исправный сервер. Доступность провайдеров контролируется отдельно по реальным тестовым операциям и их кабинетам.

## Размещение первой версии

Файловое хранилище рассчитано на один экземпляр ORBITA. Разместите процесс за HTTPS-прокси и подключите один постоянный приватный диск. Не запускайте несколько реплик с общей сетевой папкой: файловые блокировки проекта не являются распределёнными.

При размещении заполните `ORBITA_TRUSTED_PROXY_IPS` точными адресами прокси, который непосредственно соединяется с Node.js. Прокси должен перезаписывать `X-Forwarded-For` реальным адресом клиента либо корректно добавлять его справа. Приложение разбирает цепочку справа и доверяет только явно перечисленным узлам; заголовок от обычного клиента игнорируется. Не указывайте `*`, адреса клиентов, маски или неизвестные узлы. В локальном запуске оставьте поле пустым. Строгий preflight требует эту настройку; адреса определяются при выборе хостинга, а не подставляются заранее.

Лимиты и объём защиты описаны в [security.md](security.md). Внешний прокси должен закрывать прямой доступ к порту Node.js, ограничивать соединения и обрабатывать внешнюю фильтрацию трафика. В этом этапе размещение не выполняется.

Каталог резервных копий должен быть отдельным от `ORBITA_DATA_DIR` и `public`. Фраза шифрования хранится в секретах хостинга, отдельно от самих копий. До допуска к продажам восстановите одну копию в новой тестовой папке и проверьте вход, MFA, идеи, подписки и платёжный журнал.

## Ошибки и остановка

Аккаунты, идеи и общая проверка баз используют предел 32 МиБ на JSON-файл, совместимый с ограничением файла зашифрованной копии; новости имеют отдельный предел 1 МиБ. Ошибка структуры, подменённая ссылка либо исчерпание ревизии останавливает действие без замены прежнего файла. Каталоги данных для `manage-access` и импорта проверяются на приватность и расположение вне `public`. Подробности последней проверки — в [project-audit-2026-10-31.md](project-audit-2026-10-31.md).

Неожиданный серверный сбой получает безопасный `errorId`. Тот же идентификатор, маршрут и технический код появляются в stderr; тело запроса, cookie, email, пароль и токены туда не пишутся. Пользователь может передать поддержке только `errorId` и время события.

При `SIGTERM` или `SIGINT` сервер сначала снимает готовность, перестаёт принимать новые соединения, останавливает таймеры и ожидает HTTP-запросы, очередь уведомлений, письма и уже запущенные фоновые операции. Если за десять секунд завершение не произошло, соединения закрываются, а процесс завершается с кодом `1`, чтобы хостинг зафиксировал ошибочную остановку.
