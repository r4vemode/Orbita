Отчёт по ТЗ (раздел 14). Аудит рыночных данных подробно — в [markets-audit.md](markets-audit.md).

## 1. Что реализовано и исправлено

**Авторизация (P0).** Найденные причины «выхода» при переходах:
1. Логотип во всех разделах вёл на лендинг, где всегда была кнопка «Войти» — выглядело как выход. Теперь логотип ведёт в «Стратегии», а лендинг при активной сессии показывает «Кабинет».
2. Навигация отличалась на каждой странице; часть ссылок вела на страницы, которые отправляли на `/subscriptions.html` или `/account.html` (например, при неверно рассчитанных правах EXCLUSIVE).
3. Сессия жила фиксированные 7 дней без продления. Теперь скользящая: активность продлевает окно до 7 дней (не чаще раза в час), абсолютный предел — 30 дней; истёкшая сессия не воскрешается.

После входа клиент попадает в «Стратегии» (администратор — в редакцию), исходный защищённый URL восстанавливается через `next` (сервер повторно проверяет права). Платный контент не мигает: страницы и ассеты проверяются сервером до отдачи, лента отрисовывается только после ответа API.

**Тарифы (P0).** Централизованная модель в `lib/access.mjs`: уровни `pro < exclusive`, `effectiveTier`, `canReadTier`, `tierOf(strategy)`. Ошибка «EXCLUSIVE не видит PRO» исправлена во всех местах (идеи, дашборд, уведомления, Radar).

**Стратегии (P0).** `/strategies.html` — один раздел, две вкладки, фильтры (инструмент, направление, статус, стратегия, дата), карточки: тикер/инструмент, LONG/SHORT, PRO/EXCLUSIVE, вход/стоп/цели, R/R, дата и время, горизонт, статус, результат (только для закрытых с ценой выхода), ссылка на анализ. Цвета: PRO голубой, EXCLUSIVE приглушённый золотой, LONG зелёный, SHORT красный — только в метках.

**Админка (P0).** Выбор стратегии сгруппирован «PRO / Дейтрейдинг» и «EXCLUSIVE» (EXCLUSIVE доступен для любого рынка); предпросмотр с графиком и уровнем доступа; новые события: перенос между стратегиями (журнал «PRO → EXCLUSIVE»), архив/возврат, публичный пример; дополнительные цели (до 4); фильтр списка по тарифу и статусу. Telegram-бот использует тот же `ideas.create/update` и ту же модель доступа.

**Графики (P1).** `assets/idea-chart.js`: 4 схемы LONG и 4 SHORT, детерминированный выбор и шум (хэш id → PRNG), масштаб по входу/стопу/всем целям, тонкие линии, подпись «Схема … · не история цены». Используется в карточках и в предпросмотре редакции. Реальные OHLC для акций не подключались (нет лицензированного источника) — поэтому только схема.

**Лендинг (P1).** Блок «Посмотрите, как работают идеи ORBITA» (`GET /api/public/showcase`): инструмент, направление, даты, статус, расчётный результат только для активной идеи с проверенной свежей ценой MOEX (формулы для LONG/SHORT, источник, время, задержка). Уровни, разбор и комментарии не передаются. Закрытая/отменённая/архивная/перенесённая в EXCLUSIVE идея снимается автоматически; без примера — нейтральное состояние.

**App Shell (P0/P1).** `assets/shell.js` + `shell.css`: одна навигация (Стратегии, Radar, Рынки, Калькулятор, Обучение, Подписка, Настройки + Моя Орбита, Уведомления, Поддержка, Где торговать, Редакция для админа), sticky-сайдбар на ≥1024 px, компактное меню на мобильных, индикация страницы и тарифа, выход. Стили страниц не влияют на навбар.

**Email и безопасность (P1).** Три компактные секции; читаемые Primary/Secondary кнопки с hover/focus/disabled; кнопка «Панель администратора» видна только администратору; смена пароля и отправка письма неактивны, если почта не настроена.

**Визуальный шум (P1).** Единые токены (`--o-h1` 26–34 px, карточки 18–21 px, текст 14–15 px), один набор кнопок `o-btn-primary/secondary/tertiary`, состояния загрузки/пусто/ошибка; огромные заголовки старых внутренних страниц приведены к общей шкале.

**Рынки (P0/P1).** Новый модуль `lib/markets/*`, страница `/markets.html`, диагностика `/markets-admin.html` — см. аудит.

## 3. Как работает PRO/EXCLUSIVE

| Пользователь | PRO | EXCLUSIVE |
|---|---|---|
| Без подписки | нет | нет |
| PRO | да | нет (вкладка заблокирована, данных нет) |
| EXCLUSIVE | да | да |
| Администратор | да | да |

Проверка на сервере при каждом запросе: `/api/ideas` фильтрует записи и отдаёт `locked: [...]`; `/api/ideas/:id` возвращает одинаковый 404 для несуществующей и недоступной идеи (нельзя перебрать ID); страницы/ассеты защищены до отдачи; ответы `Cache-Control: no-store`, `Vary: Cookie`; WebSocket нет; SSE Radar проверяет доступ. Истечение подписки и снятие тарифа действуют на следующий запрос. Тестовое назначение тарифа — существующая форма в редакции (`/api/admin/subscriptions`: дата окончания, обязательное основание, журнал `accessAudit`). CloudPayments уже реализован (HMAC-проверка вебхуков check/pay/fail/refund/recurrent, рекуррент, возвраты); в этом выпуске не менялся.

## Дополнение (второй заход)

* **Администратор из консоли:** `ORBITA_ADMIN_PASSWORD='…' node scripts/manage-access.mjs create-admin <email>` — создаёт подтверждённого администратора или сбрасывает ему пароль (все его сессии завершаются). Пароль можно ввести и через stdin. На HTTPS-сайте при первом входе потребуется настроить 2FA.
* **После регистрации** — сразу «Стратегии» с приветствием: подсказка подтвердить email и подключить тариф. **После оплаты** (возврат из CloudPayments) — как только сервер подтвердил подписку, клиент автоматически попадает в ленту идей купленного тарифа.
* **Компактная лента:** одна строка на идею (время, инструмент, LONG/SHORT, вход, стоп, цель, R/R, статус, итог), группировка по дням, быстрые фильтры «Открытые / В сделке / Ждут входа / История», раскрытие строки — разбор, условия, график. Для активных идей — «сейчас ±x%» по проверенной цене MOEX (акции TQBR, фьючерсы FORTS; задержка ~15 мин указана в подсказке).
* **Понятность:** блок «Как пользоваться идеями — 1 минута» (скрывается), расшифровка LONG/SHORT, R/R; на лендинге — «1. Получаете идею · 2. Видите точные цены · 3. Решаете сами».
* **Статистика результатов:** `GET /api/public/stats` — только агрегаты по закрытым реальным идеям (без демо и ошибочных): число, доля в плюсе, средний результат в % и в рисках (R). На лендинге показывается от 5 закрытых PRO-идей.
* **Radar:** раскрывающаяся инструкция «Что это / Как читать карточку / Как использовать».
* **Рынки:** колонка «Толпа (физлица)» — отклонение нетто-позиции физлиц от среднего за 20 сессий (σ), «экстремум» при |z| ≥ 2; совмещённый график расчётной цены и нетто физлиц; блок «Зачем этот раздел».
* **Telegram:** новая настройка «Крайние позиции на фьючерсах» — сообщение при экстремуме, не чаще раза в день на инструмент (ключ инструмент+дата).

## Дополнение 3: уведомления, результаты, калькулятор, дайджест, PWA, светлая тема

* **Мгновенные уведомления.** Любое событие по идее (публикация, вход, стоп, цель, перенос стопа/цели, отмена) сразу запускает отправку, без ожидания минутного цикла; минутный цикл остаётся страховкой. Сообщения короткие: «✅ SBER LONG: цель 329 ₽ достигнута · +5,31%», ссылка последней строкой.
* **История результатов** — публичная страница `/results.html` и `GET /api/public/results`: все завершённые реальные идеи без отбора (в плюсе, в минусе, отменённые, ошибочные), уровни при публикации и итоговые, перенос стопа/цели, % и результат в R от первоначального стопа, кривая накопленного R, скачивание CSV. Уровни открытых идей не раскрываются — только их число.
* **Калькулятор позиции в идее** («Сколько брать»): капитал и % риска → лоты (акции — размер лота MOEX TQBR), контракты (фьючерсы — стоимость шага цены и ГО MOEX), объём (крипта). Предупреждения: позиция больше капитала, ГО больше капитала, риск на 1 лот больше допустимого. Значения запоминаются на устройстве.
* **Утренний дайджест 9:30 МСК** (будни, одно сообщение, настройка «Утренний дайджест»): открытые идеи пользователя, крайние позиции физлиц на фьючерсах, топ событий Radar за ночь, главные новости за ночь из ленты `news.json` (отбор по правилам: срочные → с упоминанием компаний → с явной тональностью; это не ИИ-пересказ).
* **PWA и push без Telegram:** манифест, иконки, service worker (кеширует только оформление; страницы и API — всегда из сети, платные данные не кешируются; офлайн — страница «Нет связи»), кнопка «Установить приложение», включение push на устройстве в «Уведомлениях». Web Push реализован на `node:crypto` (RFC 8291 aes128gcm — проверено на эталонном векторе RFC; VAPID RFC 8292), адреса подписок ограничены push-сервисами браузеров (без SSRF). Push — второй канал той же системы уведомлений: те же настройки, права и события.
* **Светлая тема** для кабинета и админки (лендинг остаётся тёмным). Переключатель в меню: тёмная (по умолчанию) → светлая → как в системе; выбор применяется до отрисовки (без вспышки). Светлые стили генерирует `node scripts/build-light-theme.mjs` (по файлу на каждый исходный CSS, правила видны только при `html[data-theme=light]`), ручные правки — `theme-light-fixes.css`. Проверка: автоматический аудит контраста WCAG всех текстов на 26 страницах × 3 роли × 2 ширины — 0 нарушений.
* Исправлено по ходу: «Моя Орбита» у EXCLUSIVE показывала PRO как «Не подключена» — теперь «Входит в Exclusive».
