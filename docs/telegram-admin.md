# Telegram · сигналы

Закрытый Telegram Admin Bot позволяет публиковать и сопровождать идеи без открытия сайта. Он использует тот же сервис и `ideas.json`, что и редакция. Веб-админка сохраняет свои функции; опубликованный из Telegram сигнал доступен в ней по прямой ссылке `/admin.html?idea=…` и отмечен источником Telegram.

Бот выключен по умолчанию. Локальный `npm start` и учебная среда работают без его токена и без внешних запросов. Реальные webhook и сообщения требуют отдельного бота, публичного HTTPS-сайта и настройки владельцем. Автоматические проверки используют вымышленные аккаунты и замену транспорта.

## Быстрая публикация

Отправьте одной строкой:

```text
SBER 312.5 307 325
```

Порядок фиксирован: **тикер, вход, стоп, тейк**. Бот определяет LONG при `стоп < вход < тейк` и SHORT при `тейк < вход < стоп`. Поддерживаются строчные тикеры, десятичная запятая, команды `/s` и `/signal`, а также явное направление:

```text
sber 312,5 307 325
/s SBER 312.5 307 325
SBER SHORT 312.5 318 300
```

Предпросмотр показывает стратегию, уровни, риск, потенциал и Risk/Reward. «Опубликовать» создаёт обычную идею в общей базе; «Изменить» позволяет исправить инструмент, направление или любой уровень. Длинный комментарий не требуется. Подробный разбор можно добавить через сайт. В действии «Изменить описание и разбор» также доступна HTTPS-ссылка на график: клиент открывает её отдельно, без встраивания внешней страницы.

При вводе `SBER 312 307` бот попросит недостающий тейк — достаточно ответить `325`. Команда `/cancel` и кнопка отмены удаляют текущий ввод. Временная сессия истекает через 30 минут; оператор может задать от 1 до 120 минут через `TELEGRAM_ADMIN_DRAFT_TTL_MINUTES`.

После публикации состояние — **WAITING**, пока автор отдельно не подтвердит вход. Запланированный уровень не выдаётся за исполненную сделку. Сигнал появляется в обычной ленте и существующей системе уведомлений; отдельная Telegram-рассылка клиентам ботом администратора не создаётся.

## Меню и сопровождение

`/start` открывает меню, `/help` — формат ввода. «Новый сигнал» необязателен: полную строку можно отправить сразу. `/active` показывает активные и ожидающие идеи, «Последние» — недавние записи.

В карточке доступны изменение стопа и тейка, подтверждение входа, отмена до входа и закрытие активной идеи. Изменение требует подтверждения; при закрытии бот сначала спрашивает цену и показывает результат автора. Если идея уже изменена через сайт или другим действием, бот предлагает проверить актуальную карточку, сохраняя историю.

По инструменту с открытой или ожидающей идеей появится предупреждение с переходом к существующей записи. Создать ещё одну можно отдельным подтверждением. Предупреждение действует и при включённой мгновенной публикации.

Уже опубликованная история не удаляется бесследно: ошибочная публикация отмечается через веб-редакцию с причиной. Первоначальные условия и последующие изменения сохраняются. Telegram ID и служебные ключи повторной обработки не включаются в клиентские карточки.

## Стратегия, инструменты и Instant Publish

На странице `/telegram-admin.html` администратор выбирает стратегию по умолчанию. Для инструмента другого рынка бот использует подходящую стратегию: акции, фьючерсы и криптовалюты не смешиваются. Выбранная стратегия показана в предпросмотре.

Instant Publish по умолчанию выключен и включается отдельно для привязанного администратора с явным подтверждением в настройках. В этом режиме корректная полная строка может публиковаться сразу; предупреждение о дубликате остаётся. Отключить режим можно там же.

Инструмент проверяется по общему справочнику и ранее опубликованным реальным идеям проекта. Для неоднозначного запроса бот предлагает варианты; неизвестный тикер не публикуется автоматически. Новый инструмент сначала можно завести корректной публикацией через веб-редакцию. Учебные идеи справочник не расширяют.

Справочник не является потоком котировок и не подтверждает актуальный листинг. Фьючерсный корень вроде `SI` обозначает семейство: перед рабочей публикацией проверьте конкретный контракт и срок исполнения; точный тикер может быть взят из существующей реальной идеи. Котировки и предупреждение об отклонении входа от рынка требуют будущего подключения источника. В этой версии один тейк; несколько целей и синхронизация карточки Telegram после каждого веб-изменения оставлены для развития.

## Подключение на своём сервере

1. Подготовьте публичный HTTPS-домен по [серверной инструкции](../START-SERVER.md). Создайте и защитите MFA аккаунт администратора.
2. Создайте **отдельного** бота через BotFather. Не используйте токен бота клиентских уведомлений: у одного Telegram-бота может быть только один webhook.
3. В приватном окружении сервера заполните переменные из `.env.example` или `deploy/.env.example`:

```dotenv
TELEGRAM_ADMIN_BOT_ENABLED=true
TELEGRAM_ADMIN_BOT_TOKEN=
TELEGRAM_ADMIN_BOT_USERNAME=
TELEGRAM_ADMIN_WEBHOOK_SECRET=
TELEGRAM_ADMIN_DRAFT_TTL_MINUTES=30
```

Токен и secret не отправляйте в чат и Git. Secret — случайная строка длиной 32–256 символов из букв, цифр, `_` и `-`. `ORBITA_PUBLIC_ORIGIN` должен быть точным HTTPS-origin сайта. Для клиентских уведомлений сохраняются отдельные `TELEGRAM_BOT_*` и `TELEGRAM_WEBHOOK_SECRET`.

4. Перезапустите приложение с этим окружением. Проверка конфигурации покажет неверные или несовместимые значения. Старт сервера сам webhook не регистрирует.
5. Из корня проекта явно зарегистрируйте webhook:

```sh
node --env-file=.env scripts/setup-telegram-admin.mjs --set
```

Для Docker Compose процедура размещения использует приватный `deploy/.env`; после пересборки образа команда внутри приложения — `orbita_dc exec app node scripts/setup-telegram-admin.mjs --set`. Используйте её после применения переменных и доступности HTTPS. Команда сверяет username через `getMe`, регистрирует `/api/telegram/webhook` с secret и не удаляет ожидающие обновления.

Состояние можно проверить без изменения webhook:

```sh
node --env-file=.env scripts/setup-telegram-admin.mjs --status
```

Если окружение уже загружено, доступны `npm run telegram:admin:webhook` и `npm run telegram:admin:webhook -- --set`. Вывод сообщает совпадение адреса и число ожидающих обновлений, без токена, URL API и исходных ошибок провайдера.

6. В веб-редакции откройте «Настройки → Telegram · сигналы», нажмите подключение и отправьте `/connect КОД` в **личный чат** с ботом. Код одноразовый и действует десять минут. Username не является способом авторизации: сохраняется числовой Telegram user ID, связанный с текущим администратором.
7. Оставьте Instant Publish выключенным для первой проверки. Опубликуйте согласованную тестовую идею через предпросмотр и проверьте её в веб-редакции. Затем проверьте изменение стопа, подтверждение входа и закрытие. Тестовую ошибочную публикацию пометьте с причиной; не выдавайте учебный пример за рабочий сигнал.

## Доступ, повторы и сохранность

Действующая роль администратора и состояние защиты проверяются при каждом действии. Снятие роли, смена пароля, изменение MFA или отключение привязки прекращают прежний доступ. Повторная привязка требует нового одноразового кода из сайта. Кнопка отключения доступна и при выключенном боте, если привязка сохранилась.

Webhook проверяет secret до чтения команды. Принятые обновления попадают в ограниченную очередь в существующем `accounts.json`; там же хранятся привязки и временные сессии. Коды подключения сохраняются только в виде хеша, включая ожидающую обработку. Сигналы остаются в `ideas.json`. Повтор доставки, повтор кнопки и восстановление после перезапуска не должны создавать вторую публикацию или второе событие изменения.

Резервная копия включает общие аккаунты и идеи. Она содержит чувствительные административные связи, поэтому храните её зашифрованной по [инструкции резервного копирования](backups.md). После аварийного восстановления проверьте актуальность привязок и опубликованных сигналов до продолжения работы. Не запускайте вторую копию приложения с той же рабочей базой для параллельной обработки webhook.
