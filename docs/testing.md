# Как проверить личный кабинет

Для полного ЛК нужен Node.js 20+ и сервер. Для отдельного прототипа AlgoPack сервер не нужен: распакуйте `demos/Orbita-AlgoPack-demo.zip` и откройте `index.html`.

## Запуск основного проекта

Скачайте ветку `codex/orbita-ready` из GitHub через Code → Download ZIP, распакуйте и откройте терминал в папке с `package.json`. Выполните:

```sh
npm start
```

Откройте адрес из терминала. Двойной клик по `public/index.html`, Live Server и GitHub Pages не запускают API аккаунтов. Зависимостей npm и сборки нет. Не используйте рабочую базу для экспериментов с выдачей доступа.

## Два браузера, два аккаунта

1. В обычном окне зарегистрируйте аккаунт владельца. Нужен пароль от 10 символов и оба согласия. Если почта не настроена, страница безопасности честно сообщит об этом; ручная тестовая подписка всё равно позволяет проверять ЛК.
2. В другом браузере или режиме инкогнито зарегистрируйте клиента. Не выдавайте ему подписку сразу: прямой переход на `/app.html`, `/calculator.html` или `/learn.html` должен перенаправить на выбор подписки. Публичная страница стратегии показывает описание, а не платные сигналы.
3. В терминале из корня проекта назначьте владельца администратором:

```sh
node scripts/manage-access.mjs admin owner@example.com
```

Подставьте email, который только что зарегистрировали. Если сервер использует `ORBITA_DATA_DIR`, задайте тот же каталог для этой команды. Стандартного логина или пароля администратора нет.

4. В окне владельца откройте `/admin.html`. Для HTTPS-сайта двухфакторная защита администратора обязательна по умолчанию: сначала откроется `/security.html`. Добавьте ключ в приложение-аутентификатор, подтвердите код и сохраните резервные коды. В локальном запуске без настройки HTTPS MFA можно включить вручную.
5. В «Подписки клиентов» выберите тестового клиента, Pro, будущую дату окончания и причину «Тест MVP». Нажмите «Сохранить доступ».
6. В окне клиента откройте `/app.html`. Если идей пока нет, это нормально: новая база пустая.

## Публикация и сопровождение

В окне владельца опубликуйте `SBER`, лонг, стратегию `Momentum RU`. После публикации без уровней должен показываться анонс; цены и результат не выдумываются. Добавьте комментарий, затем уровни и условия, подтвердите вход и измените стоп. В клиентском окне обновите идеи и проверьте журнал и первоначальные условия.

Отметьте «Я вошёл», задайте свою цену и количество. После закрытия сравните результат автора и личной сделки. Опубликованную идею нельзя удалить: ошибка отмечается с причиной и остаётся в истории.

Отдельно опубликуйте идею стратегии `Orbita Exclusive`. Подписчик Pro не должен видеть её даже по прямому URL/API. Выдайте клиенту только Exclusive вместо Pro и проверьте обратное разделение. Тарифы независимы.

## Отзыв доступа

В редакции отзовите подписку клиента. В его действующей сессии обновите ЛК: доступ должен закрыться. Проверьте ещё раз через верхнее меню лендинга, страницу стратегии и прямой адрес идеи. Настройки безопасности, уведомлений и подписок остаются доступны, чтобы человек мог управлять аккаунтом и отключить рассылку.

## Оплата, почта и Telegram

Без реальных настроек эти кнопки не изображают успех. Сам ЛК проверяется ручной выдачей доступа, без перевода денег. Настройка интеграций описана в [integrations.md](integrations.md), резервных копий — в [backups.md](backups.md).

CloudPayments сначала проверяется в тестовом режиме с тестовым магазином. Возврат из платёжной формы не является подтверждением оплаты: подписку выдаёт только сервер после проверки подписанного Pay-уведомления. Реальные списания, доставку писем и Telegram нужно отдельно проверить в настроенной среде.

## Автоматические проверки

```sh
npm test
python3 -m unittest discover -s telegram -p 'test_*.py'
```

Тесты используют временные каталоги, фиктивные транспорты внешних провайдеров и локальные HTTP-серверы. Они не списывают деньги и не отправляют сообщения реальным пользователям.
