# Аудит фьючерсных данных и раздела «Рынки» (08.11.2026)

Проверено на живых ответах MOEX ISS в воскресенье 08.11.2026 (идёт выходная сессия; последний завершённый клиринговый день — пятница 06.11.2026; 04.11 — праздник, торгов не было).

## 1. Что было до доработки

| Вопрос ТЗ | Ответ |
|---|---|
| Откуда парсились данные по фьючерсам | Модуль `lib/participants.mjs` + `lib/participants-model.mjs` («Позиции участников», `participants.html`). Источник — MOEX ISS, набор **FUTOI** (AlgoPack): `GET https://iss.moex.com/iss/analyticalproducts/futoi/securities.json?date=<сегодня МСК>`; справочник `…/engines/futures/markets/forts/boards/RFUD/securities.json`; состав IMOEX `…/statistics/engines/stock/markets/index/analytics/IMOEX/tickers.json`. С ключом — `apim.moex.com`. |
| Какие показатели | Длинные/короткие позиции физ- и юрлиц (`pos_long`, `pos_short`, `clgroup=FIZ/YUR`). Цен, объёма, ОИ контракта, экспирации — не было. |
| Реальные запросы или хардкод | Реальный адаптер был, но **выключен по умолчанию** (`MOEX_POSITIONS_MODE=off`). В этом режиме пользователь видел только кнопку «учебный пример» с вымышленными числами из `fixtures/participants-demo.json`. Отдельная страница `market-demo.html` («Рынок · демо» в меню) — полностью **синтетические** данные (свечи, скринер), не связанные с биржей. |
| Кеширование | Снимок хранился в `data/participants.json`; «устаревание» — 30 мин (`MOEX_POSITIONS_STALE_MINUTES`). |
| Фоновое обновление | `setTimeout`-цикл в самом модуле (интервал 300 с, экспоненциальный backoff до 1 ч). Запускался, только если `MOEX_POSITIONS_MODE=moex`. |
| Когда реально обновлялось | В поставленной копии `data/` нет — значит, на этой сборке не обновлялось ни разу. |
| **Почему данные неактуальны** | 1) режим `off` по умолчанию → интерфейс показывал демо/пустоту; 2) **бесплатный FUTOI не отдаёт данные за последние 14 дней**. Запрос с `date=<сегодня>` возвращает `ERROR_MESSAGE: "Invalid date. Free users can't receive data for the last 14 days (2026-10-25)"`; без даты — снимок 23.10.2026. Код ожидал таблицу `futoi`, получал ошибку и записывал `MOEX_SOURCE_UNAVAILABLE`; 3) даже при наличии ключа порог «устарело через 30 минут» помечал бы дневные данные как устаревшие каждую ночь и выходные. |
| Ограничения API | FUTOI: актуальные данные только по подписке AlgoPack (APIKEY). ISS без ключа: котировки с задержкой ~15 минут (проверено: `UPDATETIME` отстаёт от `SYSTIME` на 15 мин). |
| Права на коммерческое использование | Отображение биржевой информации в платном продукте регулируется договором/правилами распространения информации MOEX. В коде это **не подтверждено**; см. раздел 6. |

Вкладка «Позиции участников» решала узкую задачу (доли физ/юр в FUTOI), дублировала часть Radar по смыслу «рыночного контекста», а «Рынок · демо» показывал вымышленные котировки рядом с реальными разделами.

## 2. Новое назначение разделов

| Раздел | Задача пользователя |
|---|---|
| **Стратегии** | Опубликованные идеи с уровнями (PRO / EXCLUSIVE). |
| **Radar** | Корпоративные события, новости, катализаторы. |
| **Рынки** (`/markets.html`) | Объективное состояние фьючерсов MOEX: цена, итоги последней сессии, открытый интерес, позиции физ/юрлиц и их динамика, экспирация, ссылки на открытые идеи ORBITA по тому же инструменту. |

`/participants.html` и `/market-demo.html` теперь перенаправляют (301) на `/markets.html`. API `/api/participants/*` сохранён для совместимости.

## 3. Источники (каждый показатель — свой источник и частота)

Все — официальный MOEX ISS, фиксированный хост `https://iss.moex.com/iss` (с `MOEX_API_KEY` — `https://apim.moex.com/iss`). Обработчик: `lib/markets/service.mjs`, нормализация: `lib/markets/model.mjs`, хранилище: `data/markets.json`.

| Показатель | Endpoint | Актуальность | Обновление |
|---|---|---|---|
| Последняя цена, изменение к закрытию пред. сессии (`LASTTOPREVPRICE`), объём за день, ОИ контракта | `/engines/futures/markets/forts/securities.json` (1 запрос на весь рынок) | Текущая сессия, **задержка ~15 мин** без ключа | каждые 300 с (`MARKETS_QUOTES_INTERVAL_SECONDS`) |
| Цена закрытия, расчётная цена, объём сессии, ОИ контракта | `/history/engines/futures/markets/forts/securities/{SECID}.json` | **T−1** — последняя завершённая сессия | каждые 3600 с (`MARKETS_DAILY_INTERVAL_SECONDS`) |
| Открытые позиции физ/юрлиц: лонг/шорт в контрактах, число лиц в лонге/шорте, изменение за сессию | `/statistics/engines/futures/markets/forts/openpositions/{ASSET}.json[?date=]` | **T−1**, бесплатно, без 14-дневной задержки FUTOI | каждые 3600 с; одноразовая догрузка 20 последних сессий для динамики |
| Контракт, экспирация, лот, шаг цены | тот же `securities.json` | справочник | вместе с котировками |

Выбор контракта: живой контракт базового актива с наибольшим ОИ на предыдущем клиринге, при равенстве — ближайшая экспирация.

**Методика ОИ.** В ISS поле `OPENPOSITION` считает обе стороны. Проверка 06.11.2026 по Si: сумма `OPENPOSITION` всех контрактов = 9 913 346; статистика открытых позиций: лонги = шорты = 4 956 673 = 9 913 346 / 2. ORBITA показывает ОИ как число открытых контрактов (`OPENPOSITION / 2`).

**Позиции ≠ ОИ.** Нетто физлиц и юрлиц всегда равны по модулю и противоположны (это две стороны одних контрактов). Доли — доли контрактов, не людей. Интерфейс это поясняет.

## 4. Сегодня или T−1

* Даты сессий берутся **из ответов биржи** (история, статистика позиций), а не вычитанием календарного дня. Нерабочие дни возвращают пустой снимок и пропускаются; праздник 04.11 в истории отсутствует.
* Выходные сессии MOEX (сб/вс) относятся к клиринговому дню понедельника (`TRADE_SESSION_DATE`). Поэтому в воскресенье «последняя завершённая сессия» — пятница, что и показывается.
* Каждое значение подписано датой/временем и источником: «Позиции на 06.11.2026 (последняя сессия) · MOEX», «Цена на 08.11, 14:34 МСК · задержка ~15 мин».
* Устаревание: котировка старше 90 мин (`MARKETS_QUOTE_STALE_MINUTES`) или дневные данные старше 5 дней / без успешной синхронизации 36 ч (`MARKETS_DAILY_STALE_DAYS`) помечаются «устарело». Слово «сегодня» не используется для вчерашних данных.
* Для публичного результата на лендинге используется только свежая (не «устаревшая») цена.

## 5. Надёжность

Последовательная очередь запросов с интервалом 300 мс; до 2 повторов с паузой 1 с / 3 с при сетевых ошибках (ошибки провайдера не повторяются); одна задача каждого типа одновременно; ручной запуск администратора — 409 при выполняющемся обновлении и не чаще раза в 60 с; при сбое сохраняется последнее валидное значение с датой; записи дедуплицируются по дате; журнал 30 последних запусков; атомарная запись файла с fsync. Диагностика: `/markets-admin.html` и `GET /api/admin/markets`.

## 6. Ключи, оплата, лицензия

| Источник | Ключ | Оплата/лицензия |
|---|---|---|
| ISS котировки/история/openpositions | не нужен | Для показа в **платном** продукте требуется проверить и, вероятно, заключить договор с MOEX о распространении биржевой информации (в т.ч. задержанной). До подтверждения на публичном HTTPS-сайте раздел выключен: `MARKETS_LICENSE_CONFIRMED=true` включает его осознанно. |
| FUTOI / AlgoPack (реальное время) | `MOEX_API_KEY` | Подписка AlgoPack + отдельные права на распространение. |
