# ORBITA — подготовка выпуска от 2 ноября 2026 года

Локальная часть выпуска дополнена главным экраном ЛК и повторяемой проверкой Docker-сборки. Сервер и домен ещё не выбраны; публичное развёртывание и реальные подключения не выполнялись.

## Что завершено

«Моя Орбита» (`/dashboard.html`) собирает собственные ручные позиции, обновления выбранных идей, доступный Radar и ответы поддержки. Без подписки экран остаётся доступным, а платные данные закрыты на сервере. Подтверждённый клиент после обычного входа открывает этот экран; прямые ссылки на идеи и выбранные тарифы сохраняются. Порядок входа администратора и MFA сохранён.

Pro и Exclusive имеют независимые карточки, сроки МСК и напоминания за 72 часа, за сутки и в течение семи дней после завершения. Продление выполняется вручную отдельным платежом. Автосписания и внешняя доставка напоминаний не добавлены. [Описание экрана](dashboard.md).

Личная запись без выхода не пропадает после закрытия идеи автором: клиент видит просьбу проверить свою позицию. Доступ и владелец сводки проверяются до и после загрузки источников; устаревшие данные скрываются при смене аккаунта. Сбой источника отмечается недоступностью, без вымышленных котировок или нулевых итогов.

## Проверки выпуска

Все проверки используют временные вымышленные аккаунты и отдельные каталоги. Рабочие данные, реальные сообщения и платежи не используются.

| Проверка | Результат |
| --- | --- |
| `npm test` | 321/321 |
| `npm run check:mvp` | 13/13 групп, включая сводку ЛК, перезапуск и восстановление |
| `npm run check:ui` | 199/199; Chromium 154.0.8037.57, `ru-RU`, `Europe/Moscow` |
| `npm run check:container` | 6/6 групп; Docker 28.4.0, Node.js 24.22.2 |

Дополнительно проверены смена аккаунта, истечение подписки и отзыв роли администратора во время сборки сводки: устаревший приватный ответ отклоняется. Интерфейс «Моей Орбиты» просмотрен на ширинах 390 и 1440 пикселей. Браузерный прогон включает 8 групп этого экрана и 116 проверок адаптивности: 26 страниц и три раскрытых состояния на ширинах 320/390/768/1440.

Контейнерный прогон собирает текущий код, запускает приложение без root, без сети и опубликованных портов, с кодом только для чтения и без capabilities. Проверены регистрация, Secure cookie при HTTPS-origin, ограничения бесплатного аккаунта, MFA администратора, зашифрованная резервная копия с проверкой и восстановлением, штатная остановка и сохранность аккаунта, сессии и ключа после перезапуска. Собственные тестовые контейнеры, тома и образ удалены.

Повторить на машине с локальным Docker:

```sh
npm run check:container
```

Для первого скачивания закреплённого базового образа заранее выполните `docker build -t orbita-rehearsal .`: каждая команда автоматического прогона ограничена 30 секундами. Отчёт каждого прогона сохраняется в `qa-artifacts/container-*/report.json`; рабочий каталог данных для него не нужен. Скрипт отказывается использовать удалённый Docker endpoint и удаляет только собственные помеченные ресурсы.

Эта проверка не выпускает публичный сертификат и не подтверждает DNS, firewall или надёжность будущего диска. Предыдущая проверка Caddy на локальном фиктивном upstream и её ограничения сохранены в [отчёте от 31 октября](server-preparation-2026-10-31.md).

## Что нужно для публичного запуска

1. Выбрать VPS и домен, настроить DNS, HTTPS, доступ по SSH-ключу, firewall, постоянный приватный диск и внешнее наблюдение. Комплект и команды — в [START-SERVER.md](../START-SERVER.md) и [deploy/README.md](../deploy/README.md).
2. Заполнить данные исполнителя, публичный контакт поддержки, фактическое размещение и обработчиков; проверить и опубликовать документы. Пустые поля не заменены вымышленными сведениями.
3. Настроить отправителя почты и CloudPayments. На фактическом домене проверить подтверждение адреса и восстановление, оплату, независимость тарифов, отзыв доступа, чековый процесс и контрольный возврат. До этого рабочие продажи остаются закрыты.
4. Проверить внешнюю зашифрованную копию и восстановление на выбранной инфраструктуре; пройти личную приёмку и сценарии на физических iPhone и Android.
5. Подготовить собственные рыночные публикации и ритм поддержки. Источники Radar/MOEX и права на биржевые данные подключаются отдельно; учебные примеры не становятся реальной статистикой.

Технический запуск на выбранном VPS и допуск реальных продаж — отдельные шаги. `npm run preflight -- --production` должен оставаться незавершённым, пока отсутствуют реальные документы, контакты и согласованные настройки интеграций. Telegram и MOEX/Radar необязательны для строгой проверки, пока выключены и не заполнены частично. Telegram Admin Bot по новому ТЗ в этот выпуск не включён.
