# ORBITA — локальная версия MVP

Нужен Node.js 22 или новее; рекомендуется актуальный Node.js 24 LTS. Распакуйте архив в новую папку, откройте терминал в папке с `package.json` и выполните:

```sh
npm start
```

Откройте адрес из терминала. HTML-файлы двойным кликом не запускают аккаунты и подписки.

## Быстро покликать роли без настройки своей базы

```sh
npm run beta:local
```

Команда запускает отдельную временную копию с учебными идеями и четырьмя тестовыми аккаунтами: редактор, Pro, Exclusive и без подписки. Адрес, логины и случайный тестовый пароль будут в вашем терминале. Реальные почта и платежи отключены; ваш обычный каталог данных не используется. После остановки через Ctrl+C временные изменения удаляются. Подробный сценарий — в [docs/local-beta.md](docs/local-beta.md).

## Открыть редакцию

1. Создайте свой аккаунт на сайте.
2. В другом терминале из той же папки назначьте ему роль (подставьте свой email):

```sh
node scripts/manage-access.mjs admin ваш-email@example.com
```

3. Откройте `/admin.html`. Если запрошена двухфакторная защита, настройте её в разделе безопасности.
4. Вверху редакции есть «Radar · редакция», «Уроки и статьи», «Реквизиты и документы», «Настройки» и «Проверка MVP».
5. Для проверки клиентского кабинета зарегистрируйте отдельный аккаунт и выдайте ему Pro или Exclusive в разделе «Доступ клиентов». Проверяйте клиентский кабинет под этим аккаунтом: администратор имеет расширенные права.

В настройках можно заполнить автора, ритм публикаций, контакт поддержки и партнёрские ссылки. Пока значения не заданы, они остаются пустыми. Уроки можно сохранить черновиком, опубликовать для всех подписчиков либо только для Exclusive и снять с публикации.

Реквизиты и документы редактируются отдельно в `/legal-admin.html`: сначала приватный черновик и предпросмотр, затем публикация с повторным паролем и MFA, если она включена. Старые опубликованные редакции сохраняются. Пока данных исполнителя, хостинга и обработчиков нет, оставьте поля пустыми. Рабочие продажи закрыты до публикации документов и явного включения оператором; ввод ключей сам по себе оплату не открывает. Порядок — в [docs/legal-documents.md](docs/legal-documents.md).

## Посмотреть Radar

Запустите `npm run beta:local` и откройте `/radar.html` под учебным Pro или администратором. В `/radar-admin.html` можно создать событие, исправить анализ и проверить источники. Временная база содержит 16 вымышленных событий и удаляется после остановки. Для постоянной локальной базы: `npm run seed:radar`, затем `npm start`.

На обычном запуске источники отключены, новые события сами не импортируются. Pro включает Radar; Exclusive по умолчанию его не открывает. Реальные подключения настраиваются отдельно по [инструкции Radar](docs/radar.md).

## Проверить перед тестированием

```sh
npm test
npm run check:mvp
```

Вторая команда использует отдельную временную базу, проверяет перезапуск и восстановление копии, затем убирает свои тестовые данные. Она не изменяет ваши аккаунты и не отправляет письма или платежи.

Ваши данные хранятся в приватном `data/` или в заданном `ORBITA_DATA_DIR`. При обновлении используйте прежний каталог вместе с `.security-key`; порядок переноса — в `docs/testing.md` и `docs/backups.md`. Архив проекта не содержит ваших аккаунтов или секретов.

Статус каждого пункта дорожной карты: [docs/MVP-status.md](docs/MVP-status.md). Сценарии для участников беты: [docs/beta-testing.md](docs/beta-testing.md).

Повторяемый браузерный прогон четырёх ролей и установка его отдельного инструмента описаны в [docs/UI-acceptance.md](docs/UI-acceptance.md). Для вашей личной проверки достаточно `npm run beta:local`.
