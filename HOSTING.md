# Как разместить Orbita

## Какой сервер купить

Для первого запуска: **VPS, Ubuntu 24.04 LTS, 2 vCPU, 4 ГБ RAM, 60–80 ГБ SSD/NVMe**, постоянный публичный IP. Это стартовая рекомендация с запасом под ОС, образ и локальные копии, а не обещание числа одновременных пользователей. При активном Radar, росте истории и частых фоновых задачах рассмотреть **4 vCPU / 8 ГБ RAM** после измерений.

Обычный статический хостинг для HTML/PHP не подходит: нужен постоянно работающий Node.js 24 и приватное файловое хранилище. Для российских персональных данных выбирать размещение с учётом требований локализации; согласовать обработку и внешних провайдеров с юристом.

Сейчас **один экземпляр приложения**, локальный постоянный диск. Не запускать несколько реплик и не класть базу на NFS. Облачный ephemeral-диск без постоянного тома теряет аккаунты при пересоздании. Бэкапы на том же VPS не защищают от потери сервера: нужна отдельная зашифрованная внешняя копия и проверка восстановления.

## Что подготовить владельцу

- VPS, домен, SSH-ключ и административный доступ к DNS.
- Реальные реквизиты исполнителя, email поддержки и опубликованные документы.
- Учётную запись почтового провайдера и подтверждённого отправителя.
- Для продаж: CloudPayments, настройку чеков, секреты webhook. Не вставлять секреты в Git или чат.
- Для биржевых данных: согласованные права MOEX. Для Telegram: собственный бот и привязанные администраторы.

## Порядок установки

Полные команды создания каталогов, запуска и назначения администратора: [deploy/README.md](deploy/README.md). Выполнять их последовательно из `/srv/orbita/app`.

1. Установить Docker Engine и Compose plugin, обновить Ubuntu.
2. Загрузить распакованный исходный проект в `/srv/orbita/app`. Не загружать `node_modules`, старые `.env`, персональные установщики и учебную базу.
3. Создать приватные каталоги `/srv/orbita/private/data` и `/srv/orbita/private/backups` с владельцем `1000:1000`, правами `0700`, по инструкции deploy.
4. Скопировать `deploy/.env.example` в `deploy/.env` с правами `0600`; заполнить `ORBITA_DOMAIN` и уникальную `ORBITA_BACKUP_PASSPHRASE`. Остальные секреты добавлять непосредственно на сервере. Начать с отключённых реальных продаж.
5. Направить DNS A на IP VPS. Открыть 80/443, SSH ограничить административным IP; 3000 наружу не открывать.
6. Проверить конфигурацию и запустить из корня проекта:

```sh
sudo docker compose --env-file deploy/.env -f deploy/compose.yaml config --quiet
sudo docker compose --env-file deploy/.env -f deploy/compose.yaml up -d --build
sudo docker compose --env-file deploy/.env -f deploy/compose.yaml ps
```

7. Проверить HTTPS и `/readyz`, зарегистрировать свой аккаунт, назначить администратора доверенным CLI по deploy-инструкции, настроить MFA. Тестовых универсальных паролей в релизе нет.
8. Провести staging-приёмку: регистрация, подтверждение email, тестовый платёж, доступ без подписки/PRO/Exclusive, реферальный клиент в другом браузере, восстановление копии, остановка/запуск контейнера, мобильный экран.
9. После выполнения P0 из [аудита](docs/launch-audit-2026-11-09.md) отдельно включить продажи и проверить первый реальный платёж и возврат на собственном аккаунте.

## Ресурсы и контроль

Compose ограничивает приложение 1.5 CPU / 1536 МБ RAM, Caddy — 0.5 CPU / 256 МБ. Увеличение VPS само по себе эти лимиты не меняет: корректировать Compose и heap Node после измерений. Бэктесты лучше выполнять отдельно от обслуживания платящих клиентов.

Смотреть CPU, RSS/heap, рестарты, ошибки/задержку API, длительность фоновых обновлений, свободный диск и возраст внешней копии. На staging проверить реальные сценарии с 10/25/50 одновременными сессиями; при ошибках или нарушении согласованной задержки уменьшить нагрузку и исследовать причину. Короткий локальный smoke-test из 40 запросов не является оценкой ёмкости сервера.

Обновление: резервная копия → новая версия → проверки → переключение. Откат формата данных — через восстановление в новый каталог, а не запуск старого кода поверх изменённой базы. Сохранить `.security-key` и push-ключи вместе с приватными данными. Не выполнять `docker compose down -v` при обычном обновлении.
