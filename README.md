## Быстрый запуск

Нужен Node.js 22+; рекомендуется актуальный Node.js 24 LTS. Для обычного запуска npm-зависимости и сборка не нужны. Браузерная приёмка использует отдельную зависимость разработки Playwright.

Меры защиты и настройки перед размещением: [Безопасность MVP](docs/security.md).

Повторяемые проверки четырёх ролей в браузере: [Приёмка интерфейса](docs/UI-acceptance.md).

```sh
npm start
```

Откройте адрес, напечатанный в терминале. Не открывайте HTML двойным кликом, через Live Server или GitHub Pages: они не запускают сервер аккаунтов. Статический хостинг не обеспечивает защиту подписок.

Чтобы проверить новые экраны без собственной базы, почтовых ключей и списаний, используйте `npm run beta:local -- --payments`. Команда запускает отдельную временную базу с учебными ролями и локальным симулятором; адрес и случайные пароли появятся в терминале. Порядок проверки платежей и партнёров — в [локальной инструкции](docs/local-beta.md).

Настройки окружения:

- `PORT` — порт, по умолчанию 3000.
- `HOST` — адрес прослушивания, по умолчанию `127.0.0.1`; для контейнера может потребоваться `0.0.0.0`.
- `ORBITA_DATA_DIR` — постоянный каталог данных вне публичной папки, по умолчанию `data` в корне проекта.
- `ORBITA_PUBLIC_ORIGIN` — точный HTTPS-адрес опубликованного сайта без пути, например `https://orbita.example`. Он разрешает этот домен и корректный Origin за HTTPS-прокси; cookie получает флаг Secure. Произвольные домены и сторонние POST-запросы отклоняются. Не подставляйте чужой домен.
- `ORBITA_SUPPORT_EMAIL` — резервный публичный email поддержки. Заполненный адрес в общих настройках редакции имеет приоритет и учитывается preflight; адрес не заменяет реквизиты в документах.
- `ORBITA_PAYMENTS_MODE` — `cloudpayments` для обычного и серверного запуска. Значение `simulation` допустимо только для локального стенда и запрещено в production. Тестовый магазин CloudPayments использует отдельный флаг `CLOUDPAYMENTS_TEST_MODE`; это проверка внешней интеграции, которой локальный симулятор не является.

Пример настройки через окружение POSIX:

```sh
HOST=0.0.0.0 ORBITA_PUBLIC_ORIGIN=https://your-domain.example ORBITA_DATA_DIR=/path/to/persistent-data npm start
```

Укажите реальный домен, включите HTTPS на обратном прокси и постоянный диск. В PowerShell переменные задаются через `$env:ИМЯ = "значение"`, затем `npm start`. Не храните базы аккаунтов и Telegram-сессии в Git или внутри `public`.

Перед тестовым развёртыванием проверьте хранилище и согласованность настроек:

```sh
npm run preflight
```

Перед открытием продаж используйте строгий режим. Он завершится с ненулевым кодом, пока не настроены HTTPS-origin, поддержка, почта, CloudPayments, MFA и зашифрованные резервные копии, не опубликованы документы и не подтверждены рабочие продажи и чековый процесс:

```sh
npm run preflight -- --production
```

Хостинг может проверять `GET /healthz` для состояния процесса и `GET /readyz` перед направлением трафика. Эти ответы не содержат конфигурацию. Полный отчёт доступен только администратору через `GET /api/admin/readiness`.

## Доступ и администратор

1. Зарегистрируйте свой email в форме сайта, подтвердив оферту и согласие на обработку данных.
2. На сервере из корня проекта выполните (с тем же `ORBITA_DATA_DIR`, что у сайта):

```sh
node scripts/manage-access.mjs admin owner@example.com
```

Создать администратора сразу с паролем (пароль не передаётся аргументом, чтобы не попасть в историю команд):

```sh
ORBITA_ADMIN_PASSWORD='ваш-пароль' node scripts/manage-access.mjs create-admin owner@example.com
```

3. Заново откройте `/admin.html`. Роль считывается из серверной базы; перезапуск сайта после назначения не нужен. Публичной регистрации администратора и стандартного пароля нет.
4. В «Подписки клиентов» выберите email, тариф, дату окончания МСК и основание. Активируйте доступ после подтверждения оплаты. Отзыв и истечение закрывают доступ, в том числе для действующей сессии. Изменения сохраняются в серверном журнале `accessAudit`.

Без настройки CloudPayments действует ручная активация администратором. Нажатие «Выбрать тариф», регистрация, URL-параметры и localStorage не выдают доступ. При онлайн-оплате подписку выдаёт только проверенный сервером Pay-callback. Для новых рабочих счетов нужны также опубликованные документы и явные разрешения `ORBITA_LIVE_PAYMENTS_ENABLED` и `ORBITA_RECEIPTS_CONFIRMED`; ключей магазина недостаточно. Подписки независимы: Pro не открывает Exclusive, а Exclusive не открывает Pro. Базовое обучение доступно подписчикам; статьи Exclusive — только Exclusive/администратору.

На HTTPS-сайте администратору по умолчанию требуется настройка TOTP в `/security.html`; пока она не завершена, права редакции закрыты. Резервные коды показываются один раз. `/dashboard.html`, `/support.html`, `/security.html`, `/notifications.html` и `/subscriptions.html` требуют входа, но доступны без подписки. Почта подтверждается перед онлайн-оплатой; для ручного тестирования ЛК она не блокирует выданную администратором подписку.

На лендинге и публичных страницах стратегий доступны маркетинговые описания и один явно учебный пример. `/app.html`, `/calculator.html`, `/learn.html`, служебные файлы и API проверяют сессию и подписку на сервере. `/admin.html` и API публикаций/выдачи доступа требуют администратора. Проверка URL выполняется после нормализации пути, чтобы кодирование и завершающий слеш не обходили права. Полных сигналов и текстов статей в публичных JavaScript-файлах нет.

## Моя Орбита

Главный экран клиента — `/dashboard.html`: личные записи о входе, обновления отслеживаемых идей, доступные события Radar и последние ответы поддержки. После обычного входа подтверждённый клиент попадает сюда; прямой переход к идее сохраняется. `/app.html` остаётся лентой идей, а администратор по-прежнему открывает редакцию с проверкой MFA.

Экран доступен и без подписки, но платные позиции и идеи остаются закрыты сервером. Pro и Exclusive показываются отдельно, с точным сроком МСК и напоминанием за 72 часа, за сутки и в течение семи дней после завершения. На `/subscriptions.html` доступны история платежей и управление явно подключённым автопродлением. Открытие кабинета и его напоминания не создают заказ и не включают списания. [Порядок и ограничения](docs/dashboard.md).

## Публикация сигналов

В редакции достаточно тикера и направления — «Опубликовать сигнал» или Enter. По умолчанию это акции / Momentum RU; рынок и стратегию можно выбрать в раскрывающемся блоке.

Быстрый сигнал получает статус «Сигнал объявлен». Цены входа, стопа, цели и текущая цена отсутствуют: система не придумывает исполнение. Комментарии добавляются сразу. Действием «Добавить уровни» задайте условия — они запишутся отдельным событием, а исходный анонс сохранится. Подтверждение входа возможно после уровней. Только подтверждённый вход и закрытие участвуют в калькуляторе.

Полная публикация и черновик доступны отдельно. Можно менять стоп, добавлять комментарий, закрывать, отменять или отмечать ошибку. Опубликованные идеи, исходные условия и события нельзя переписать или удалить через API. Ошибочная публикация сохраняет результат и историю, но не участвует в расчётах. Конфликт версий возвращает 409; обновите список перед повтором.

Сигналы хранятся в `ideas.json`, аккаунты/хеши паролей/сессии/личные сделки — в `accounts.json`, новости — в `news.json`. Записи атомарные с блокировкой конкурирующих изменений. Новая база сигналов пустая. Демопримеры добавляются только явно для разработки:

```sh
node scripts/seed-demo.mjs
```

Девять примеров находятся в `fixtures`, вне публичной папки. Не импортируйте их в рабочую статистику. Старые локальные публикации браузера не становятся серверными автоматически: экспортируйте их из прежней версии для ручной проверки; правами и источником сигналов localStorage больше не является.

## Документы и партнёры

В редакции появились отдельные разделы:

- `/content-admin.html` — уроки и статьи: создание, предпросмотр, черновик, публикация и снятие с публикации; доступ для всех подписчиков либо только Exclusive.
- `/legal-admin.html` — реквизиты исполнителя, приватный черновик, предпросмотр оферты/политики/возвратов и публикация новой редакции с повторным паролем и включённой MFA.
- `/settings-admin.html` — общие сведения об авторе, порядок публикаций, email поддержки и три партнёрских предложения. Поля изначально пустые.
- `/launch-admin.html` — состояние приложения и агрегированные показатели запуска. Реальные и тестовые платежи не смешиваются; отсутствующие выборки показываются как «Пока нет данных».

Все четыре страницы и их API требуют администратора. Контент сохраняется в `content.json`, настройки — в `product-settings.json`, документы — в `legal.json`, с блокировкой и контролем версии. После первого сохранения библиотека уроков берётся из приватной базы; встроенные `fixtures/lessons.json` используются только при её отсутствии. Эти файлы входят в зашифрованные копии и проверку восстановления. Снятие статьи с публикации закрывает её в последующих ответах API; уже прочитанную пользователем информацию отозвать невозможно.

В футере: `/offer.html`, `/privacy.html`, `/refunds.html`. Публикация автоматически создаёт номер редакции и сохраняет полный HTML; прошлые тексты доступны по `?version=...`. Исходный снимок `ORBITA-2026-10-20` и `LEGAL_VERSION` сохраняются для истории, их не меняют при очередном выпуске. Фактически принятая версия и время фиксируются сервером при регистрации и в новых рабочих заказах. Оба флажка регистрации не предустановлены; смена условий требует повторного согласия в форме. Перед включением автопродления опубликованные условия должны соответствовать фактическим цене, периоду 30 дней, отдельному согласию, отмене и возвратам. Старую редакцию документов нельзя молча переписать.

Пока данных владельца нет, публично остаются исходные проекты документов. До коммерческого запуска укажите исполнителя, ИНН/ОГРН или ОГРНИП, адрес, поддержку, фактическое размещение и обработчиков, проверьте соответствие текстов деятельности и опубликуйте редакцию. Черновик публично не раскрывается. Проверка контрольных цифр реквизитов не заменяет юридическую проверку. Реквизиты не выдуманы. Указанный референс возврата GetCourse при подготовке был недоступен (HTTP 403); тексты подготовлены самостоятельно под ORBITA. Порядок и допуск к оплате — в [docs/legal-documents.md](docs/legal-documents.md).

`brokers.html` — публичный раздел «Где торговать». Партнёрские адреса остаются пустыми до заполнения в общих настройках редакции. Изменения видны в других браузерах после обновления страницы. Старые локальные переопределения браузера больше не используются. Переходы помечены как партнёрские.

## Radar

`/radar.html` — корпоративные события: поиск, фильтры, разбор, несколько источников, отслеживание компаний и обновления через SSE. `/radar-admin.html` — ручная публикация, исправление анализа, скрытие, объединение дублей и состояние источников. Событие не создаёт торговую идею автоматически.

Для знакомства используйте `npm run beta:local`: он добавляет 16 явно учебных событий в отдельную временную базу. Для сохранения локальных изменений доступны `npm run seed:radar`, затем `npm start`; seed запрещён для рабочего origin и базы с реальными событиями. Обычный запуск не импортирует демо автоматически.

Полный Radar по умолчанию включён в Pro; Exclusive включает все возможности Pro. Состав доступа меняется через `RADAR_ALLOWED_PLANS`. FREE выключен; при включении сервер ограничивает объём и задерживает выдачу. Внешние источники по умолчанию отключены. Объяснения строятся по правилам; для собственного AI bridge предусмотрены параметры среды. Реальные feeds, AI и котировки ещё не подключены. Настройки, endpoints, схема хранилища и ограничения — в [docs/radar.md](docs/radar.md), результаты — в [отчёте Radar](docs/radar-acceptance-2026-10-30.md).

## Рынки (фьючерсы MOEX)

Раздел «Рынки» (`/markets.html`, PRO и EXCLUSIVE) заменил «Позиции участников» и «Рынок · демо» (старые адреса перенаправляются). Источник — официальный MOEX ISS без ключа: цена, изменение и объём текущей сессии с задержкой ~15 минут; итоги сессии, открытый интерес и **открытые позиции физ- и юрлиц (лонг/шорт, число лиц, изменение) — на дату последней завершённой сессии (T−1)**. Каждое значение подписано датой и источником. Обновление — фоновые задачи сервера (котировки каждые 5 мин, итоги и позиции раз в час), диагностика и ручной запуск — `/markets-admin.html`.

Почему старый раздел показывал неактуальное, методика (ОИ, T−1, выходные сессии) и вопрос лицензии MOEX — в [docs/markets-audit.md](docs/markets-audit.md). На публичном HTTPS-сайте раздел выключен, пока не задано `MARKETS_LICENSE_CONFIRMED=true`.

## Стратегии: PRO и EXCLUSIVE

После входа клиент попадает в «Стратегии» (`/strategies.html`): вкладки «Дейтрейдинг · PRO» и «EXCLUSIVE», фильтры, карточки с уровнями и схематичным графиком. EXCLUSIVE включает всё из PRO; PRO видит вкладку EXCLUSIVE заблокированной, а сервер не передаёт ему ни одной записи этого уровня (прямая ссылка/ID → 404). Уровень доступа идеи определяется стратегией (`Orbita Exclusive` → EXCLUSIVE, остальные → PRO; неизвестная → PRO, никогда не публично). В редакции: перенос между стратегиями с записью в журнал, архив, дополнительные цели, выбор публичного примера для лендинга. Подробности — [docs/release-2026-11-08.md](docs/release-2026-11-08.md).

## Проверки

```sh
npm test
npm run check:mvp
```

Тесты запускают настоящий сервер с временными базами: регистрация/сессии, роли, бесплатный аккаунт, оба тарифа, истечение/отзыв, закодированные URL, прямые API, разделение данных аккаунтов, HTTPS-origin, неизменяемая история, быстрые сигналы, расчёты, тренажёр и отказ запуска при повреждённом хранилище.

Офлайн-тесты необязательного Telegram-моста:

```sh
python3 -m unittest discover -s telegram -p 'test_*.py'
```

Подключение Telegram описано в `TELEGRAM-START.md`. Bridge и сервер должны получать один `ORBITA_DATA_DIR`; без него используется `data` в корне проекта. Каталог проверяется на приватность и отсутствие символических ссылок. Сессия Telegram является секретной и не должна попадать в общие снимки.

Общая проверка и исправления от 31 октября: [доступ, платежи, сохранность и открытые страницы](docs/project-audit-2026-10-31.md). Браузерные сценарии повторяются командой `npm run check:ui`; порядок установки браузера — в [docs/UI-acceptance.md](docs/UI-acceptance.md).

## Перед коммерческим запуском

Заполните и опубликуйте документы, настройте реальные параметры сайта/почты, подключите тестовый магазин CloudPayments и проверьте полный цикл Pay/Refund, доставку писем, восстановление резервной копии и Telegram, если он используется на инфраструктуре размещения. Наличие кода и тестов с фиктивными транспортами не подтверждает работу реального магазина. Чеки/онлайн-касса и внешний сбор журналов требуют отдельной настройки; `ORBITA_RECEIPTS_CONFIRMED` лишь фиксирует подтверждение оператора, не выдаёт чек. Включайте рабочие продажи только после этой приёмки. Текущий MVP использует файловую базу: запускайте один экземпляр с постоянным диском. Для роста нагрузки нужен план миграции в PostgreSQL и общую очередь доставки.

Прототип AlgoPack не подключён к живому feed. До показа биржевых данных клиентам согласуйте подписку и права с MOEX. Демо содержит только синтетические данные и не изменяет историю идей и результатов Orbita.

## Подготовка сервера

Владелец разрешил подготовку размещения; VPS ещё не выбран. Комплект для Ubuntu 24.04, Docker и Caddy находится в [START-SERVER.md](START-SERVER.md) и [deploy/README.md](deploy/README.md). Публичный запуск, DNS и реальные провайдеры требуют выбранного сервера и собственных параметров.

Встроенная поддержка открывается через кабинет или помощь; административная очередь — «Обращения». Подробности — в [docs/support.md](docs/support.md).


Дополнительная проверка выпуска с локальным Docker:

```sh
npm run check:container
```

Она собирает текущий код и проверяет запуск, ограничения доступа, MFA, зашифрованную копию с восстановлением и перезапуск в изолированном контейнере. Рабочая база не используется, порты не публикуются. Итог подготовки от 2 ноября — в [отчёте выпуска](docs/launch-preparation-2026-11-02.md); эта проверка не заменяет приёмку настоящего домена и провайдеров.

## Telegram · сигналы

Отдельный закрытый бот администратора принимает `SBER 312.5 307 325`, определяет направление и показывает предпросмотр с риском и R/R. После подтверждения идея публикуется через тот же сервис, что и веб-редакция; вход подтверждается отдельно. В Telegram доступны изменение стопа и тейка, отмена до входа и закрытие с ценой и подтверждением. Стратегия и явно включаемый Instant Publish настраиваются на `/telegram-admin.html`.

Бот выключен по умолчанию. Для подключения нужны отдельный токен, HTTPS-сайт и одноразовая привязка из редакции; клиентский бот уведомлений использует другие настройки. Команда `npm run telegram:admin:webhook -- --set` регистрирует webhook только при явном запуске оператором. Порядок, права и ограничения — в [docs/telegram-admin.md](docs/telegram-admin.md).
